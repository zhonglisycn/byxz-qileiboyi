# 棋类博弈

八种棋的小米手环（Vela）快应用：**人机 / 双人**，棋盘可放大平移，字号可调。

- 产物：`dist/棋类博弈_byxz.bin`（约 281 KB，可直接安装）
- 包名：`com.byxz.qileiboyi`，版本 5.3.0
- 工程：`src/`（8 个游戏内核 + 13 个页面），工具：`tools/`

本工程是在分析原版《方寸棋阁 4.8.0》的包结构与规则后**从零重写**的：
移除了原版依赖手机 APP 的激活校验与付费档位，补齐了各棋种的完整规则，
新增井字棋，并按小米手环 10 的胶囊屏重新做了界面。

```
│   │   ├── ui.js            字号缩放 fs() + 棋盘视口（makeView/visibleCells/pan）
│   │   ├── rnd.js           纯工具
│   │   ├── util.js          唯一依赖 @system.storage 的模块（存档）
│   │   ├── ttt.js go.js xiangqi.js junqi.js chess8.js gomoku.js jungle.js aeroplane.js
│   ├── style/base.css       公共样式（深色主题 + 文字类 t-*）

└── pages/
    ├── index/menu/rules/more/about      主菜单 / 设置 / 规则 / 更多 / 关于
    └── ttt|wzq|wq|xq|gjxq|jq|dsq|fxq   八个对局页

├── run-tests.sh             跑全部内核测试
├── check-ux.mjs             页面静态检查
├── fix-text-style.mjs       补齐文字颜色（Vela 的 text 不继承父级 color）
├── preview.mjs / preview.sh 页面渲染 + 截图
├── build-bin.sh             一键构建
└── make-qr.py               生成模糊二维码占位图
```

### 两个容易踩的坑（已在代码里处理）

1. **Vela 的 `<text>` 不继承父容器 `color`**。按钮里的文字如果不自己写颜色，
   就会用默认深色 → 压在深色按钮上等于看不见。`tools/fix-text-style.mjs` 专门修这个。
2. **棋盘不要用「flex 换行 + 固定格子」**。手环上容器宽度与格子尺寸的余量很小，
   亚像素舍入就会让一行只放得下一个格子，进而压到按钮。现在统一是
   **视口 + 绝对定位格子**（每个格子的 left/top/width/height 都由 JS 算好）。

## 5. 性能与稳定性（避免手环重启）

小米手环这类设备上，**JS 线程被长时间同步阻塞会被看门狗判定为卡死并重启**。
第一版象棋 AI 在桌面就要 1.4 秒（最大 2.2 秒），换算到手环是十几到几十秒的阻塞——那就是重启的原因。

### 5.1 象棋 / 国际象棋：分片搜索

`analyseSession` / `analyseStep` 把搜索切成小片，页面每个 tick 只算 ≤10~12ms 就 `setTimeout`
让出线程（还能显示"电脑思考中 45%"）。两套搜索都用这个模式，**单次阻塞恒定在十几毫秒量级**，
所以无论局面多复杂都不会顶到看门狗。总时长由**真实时间预算**兜住（到点就交回上一层的完整结果）：

| 棋种 | 每档深度 / 预算 |
|---|---|
| 象棋 | 2层/60ms、2层/100ms、3层/160ms、3层/240ms |
| 国际象棋 | 1层/80ms、2层/180ms、3层/280ms |

### 5.2 国际象棋：把搜索里的对象分配砍掉（v5.3）

桌面测出来"最慢 200ms"，但手环上会放大成秒级——**真正被放大的是对象分配**，
小堆设备上会触发 GC 风暴甚至 OOM。原来的搜索每个节点要造几百个临时对象：

- `genPseudo` 把方向数组（马/王/车/象/后，含 `RD.concat(BD)`）写在**每枚棋子的循环里**反复重建
- 每个着法是 `{from:[x,y], to:[x,y]}` 三个对象
- `doMove` 每次造一条记录 + 一个 castling 对象，`undoMove` 又造一个新 castling 对象
- `orderMoves` 给每个着法再造 `{m,s}` 包装对象后才 `sort`
- `negamax`/`quiesce` 先用 `genLegalRaw` 走一遍 doMove/undo 筛合法性，搜索时再走第二遍

v5.3 的改法：方向常量提到模块级；`undoMove` 逐字段还原不再新建对象；`orderMoves` 边算分边插入排序；
把合法性检查挪进搜索循环（去掉重复走子）；根节点每层用上一层的最优着法先搜。

| 国际象棋 lv3（整局 57 步实测） | 改前 | 改后 |
|---|---|---|
| 平均 | 71 ms | **13 ms** |
| p95 | 138 ms | **24 ms** |
| 最慢 | 200 ms | **35 ms** |

搜索吞吐提升约 5.5 倍，而预算同时从 400ms 降到 280ms——**更快也更强**（同样时间里搜的节点更多）。

### 5.3 体感提速：收短"思考"停顿

AI 落子前原来固定停 240~300ms（飞行棋 400~700ms 还有两段 420ms/300ms 的连锁），
现在统一收到 170~240ms，飞行棋收到 240~400ms 与 260/200ms。整局节奏明显变快。

### 5.4 复现与回归

```bash
node tools/bench-ai.mjs            # 单局面：各棋种一步耗时
node tools/bench-full.mjs          # 整局 AI 对 AI：平均/p95/最慢，LV=3 指定等级（关键：残局才暴露慢步）
bash tools/run-tests.sh            # 含 3 条"不卡死"回归：单片阻塞、单步预算、预算分档递增
```

`bench-full.mjs` 是 v5.3 新增的：`bench-ai.mjs` 只测开局 3 步，而真正卡死手环的是残局，
所以必须整局打满再看最慢那一步。两个脚本都要在带 `package.json` `type:module` 的目录里跑
（做法见 `tools/run-tests.sh`）。

### 5.6 v5.3.1：分片搜索"超时后必须收敛"（象棋玩不了的根因）

`analyseStep` 原来在预算耗尽时只设了 `abort`，**没有置 `done`**。设备上搜索必然超预算，
于是页面每次调用都是"没搜完、也不推进"，靠 `setTimeout` 无限空转——表现就是
**"AI 思考一直卡在 0% 直到重启"**。桌面上永远看不出来，因为桌面搜索在预算内就跑完了，
只有手环（慢 10~20 倍）会稳定触发。

修法三处：
1. `analyseStep` 在 `sess.idx >= ordered.length **||** sess.ctx.abort` 时都必须 `done = true`；
2. 被超时中断的那一步，分数是残值（`search` 直接返回 0），不计入候选、不参与选优；
3. `analyseSession` 预先取一个**合法**兜底着法（`allLegalMoves()[0]`），保证任何情况下都出得了手。

页面再加一道保险丝：`aiRounds > 120` 强制结束会话。回归测试直接模拟最坏情况——
把 `sess.ctx.deadline` 拨到过去，断言"极少轮次内收敛 + 仍给出合法着法 + aborted 为真"。

> 教训：任何**分片 / 可中断**的循环，超时路径必须和正常完成路径一样能收敛，
> 并且必须有一个兜底结果。否则"能中断"就等于"可能永远中断在那里"。

### 5.5 渲染量

视口只渲染**可见格子**并限制档位，最重的页面从 361 个格子降到 ≤225
（飞行棋 225，围棋/五子棋 150，象棋 90，军棋 60，斗兽 63，国象 64，井字棋 9）。
格子列表用 `tid="i"` 做稳定键，落子只差量更新；每秒的计时器只改时钟文字，不整屏重渲染。

> 如果装到真机后仍然偶发重启，优先把"字体大小/棋盘档位"保持在默认，并继续下调
> `AI_LEVELS` 里的 `budget`（象棋在 `src/common/core/xiangqi.js`，国象在 `chess8.js`）。

## 7. 已知差异与限制

- **AI 强度**弱于原版：原版象棋 AI 有数十个评估函数并允许思考 10~60 秒，本作是限时 alpha-beta。
  军棋/围棋 AI 是启发式的，围棋不会做死活与形势判断（靠终局数子）。
- 围棋终局收束判据把 ≤2 点的中性空区当单官，极小概率的复杂劫/双活可能提前提示结束（只提示，不强制）。
- 五子棋禁手按主流规则实现，默认开启，可在 `newGame({forbidden:false})` 关闭。
- 军棋未实现重复局面判和；国象未实现「五十步」之外的其他和棋协议。
- 飞行棋只判「首个四方到齐者获胜」，同色跳跃已支持连续跳。
- 原版的「游戏推荐」（推广页）与「激活」页未复刻。
